# dsh-conversation-lock

给每个对话（DSH Session）配一把锁，由你决定**其他 agent** 能不能往里发消息。

每个对话默认**锁定**。锁定时，任何 agent 想往里投递消息都会被拒绝，并被告知只有你能解锁。**解锁**后，同一个 Harness 里的任何 agent 都能往这个对话投递消息。

## 出现在哪里

| 位置 | 作用 |
| --- | --- |
| 当前对话**输入框工具行里的锁按钮** | 显示「已锁定」/「已解锁」，点一下切换。 |
| 侧栏**每个会话行上的锁形图标** | 灰色闭锁＝锁定，绿色开锁＝解锁。它占用行末的图标位，鼠标悬停在该行时会隐藏。 |
| 会话「...」**菜单里的一行** | 「允许其他 agent 发消息」/「禁止其他 agent 发消息」，可以直接在列表里改锁。 |

只有你能改锁：这三处都调用只对浏览器开放的本机路由，没有任何 agent 工具能解锁对话。

## Agent 拿到的能力

每个 agent 都会拿到两个工具：

- `list_conversations`：列出这个 Host 里打开的所有对话，含锁定状态、运行状态和简短标题。
- `send_conversation_message`：按会话 ID 往某个对话投递文本。目标正在忙就在它下一步时递进去，空闲就新起一轮。成功只表示消息进了目标收件箱，不代表目标已经回复。

投递的内容是一条 user 角色的消息，来源标注为发起对话：Chat 会把它显示在带 agent 图标的 turn trigger 下，正文以
`Agent from conversation <id> sent a message:` 开头。它不是你自己写的提示词；目标也只能往同样处于解锁状态的对话里回复。

## 和另一个 agent 协作

1. 打开要接收消息的那个对话，点它的锁按钮，让它显示**已解锁**。
2. 把该对话的会话 ID 交给发送方 agent（会话菜单里有「复制会话 ID」），或者让它先调 `list_conversations`。
3. 让它调用 `send_conversation_message`。
4. 协作结束后记得把对话重新锁上。

## 限制

- 目标对话必须当前在这个 Harness 里**打开**；不活跃的对话没有 agent 能收消息，工具会直接说明这一点，而不是报「已锁定」。
- Host 没回答之前，控件不声称任何状态：读不到时什么都不显示，路由失联时锁按钮显示「不可用」（点击即重试），而不是展示一个过期的锁状态。
- 锁是每个对话的独立决定，保存在 Harness home（`$DSH_HOME/conversation-lock/state.json`），不属于对话历史。删掉该文件等于全部重新锁上。
- 只有**这个** Harness 进程里的 agent 能发。另一个 `dsh` 进程、远端查看者或别的应用都够不到已解锁的对话。
- 解锁是有意放宽策略，所以始终是用户动作：没有任何 agent 可调用的解锁入口，agent 工具在目标锁定时直接报错，而不是去申请权限。
